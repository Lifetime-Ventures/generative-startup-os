# /weekly-roast — 週次自己批判 + AI Board Meeting
# Phase: 1以降（全フェーズ）
# 推奨実行タイミング: 毎週末（金曜または日曜）
# Last Updated: v5.0

---

## Purpose

2つの機能を統合した週次レビューパイプライン：

**前段（全メンバー共通）: AI Coach Session**
4名のAIエージェントによる10ラウンド以上のコーチングセッション。
「今週やるべきことをやれたか」を多角的に問い直し、来週のコミットを整理する。
受け渡しパケットを生成してPart A（自己批判）にインプットする。

**Part A（全員）: 自己批判パケット**
memory/フォルダとNotionをスキャンし、「甘え・自己欺瞞・ドリフト」を
past decisionsを引き合いに出して冷徹に指摘する。
「今週、本当にやるべきことをやっていたか？」

**Part B（Founder専用）: 投資家・資金調達観点の検証**
資金調達・顧客開発・技術Moatの進捗を投資家視点で厳しく問い直す。

**後段（Founder・Board Meeting設定日の夜のみ）: AI Board Meeting**
context.mdの「AI Board設定」で定義した5エージェントによる仮想Board Meeting。

---

## 実行フロー

```
/weekly-roast [YYYY-MM-DD（今週の月曜）] [自分の名前]
  ↓ 自動起動（前段）
AI Coach Session（10ラウンド以上）
  ↓ 受け渡しパケット生成
Part A（自己批判パケット）
  ↓ Founderのみ
Part B（投資家・資金調達観点の検証）
  ↓ Board Meeting設定日の夜のみ・Founder専用
AI Board Meeting（context.mdのboard_membersに基づく5エージェント）
```

> メンバー（Founder以外）: AI Coach Session → Part Aのみ実行。
> Founder: AI Coach Session → Part A → Part B → AI Board Meeting（設定日夜のみ）

## Part 0：AI Coach Session（全メンバー・自動前段）

### エージェント構成（4名）

| 役割 | ペルソナ |
|------|---------|
| ファシリテーター | 中立的な議事進行役（固定・変更不可） |
| メンター | team/[name]/context.md の ai-coach-session設定を参照 |
| 提案者 | 同上 |
| 批判者 | 同上 |

未設定の場合は役割名のみで運用（毎月第1週に棚卸を実施）。

### 入力要求

```
AI Coach Sessionを開始します。以下のデータを貼り付けてください：

【今週のコミット（Doingタスク）】
[Notion Tasks DBから今週分をコピー]

【実績（Done / Delayed / Cancelled）】
[同上]

【PRRスコア】
[/weekly-roast実行前に計算 or 数値のみ]

【時間の分布（おおまかでOK）】
MTG: [X]時間 / 技術開発: [X]時間 / 管理業務: [X]時間 / 深い仕事: [X]時間

【今週のKR進捗（担当分）】
[Notion KR DBから担当KRをコピー]

【今週のモヤっていること・困っていること】
[自由記述。ここが最も重要なインプット]
```

### セッション構成（3議題・最低10ラウンド）

**議題1: 今週の目標と実績のギャップ分析**
「コミットしたタスクは達成できたか。なぜできた/できなかったか」

**議題2: リソース配分の整合性**
「時間・エネルギーはKRに向いていたか。最も価値が低かった時間の使い方は何か」
→ 深い仕事（KR直結）の割合が50%未満なら警戒ゾーン

**議題3: 来週のコミット設定と懸念事項の事前整理**
「来週3件以内のコミットを決める。今から懸念できることは何か」

10ラウンド未満で収束しそうな場合：
ファシリテーターが「まだ表面を触れているだけです」と宣言して追加ラウンドを設定する。

### 月次ペルソナ棚卸（毎月第1週）

前回棚卸から28日以上経過している場合、セッション冒頭で棚卸を実施する：
- 先月のセッションで機能しなかった視点はあったか
- ペルソナを変更する場合は team/[name]/context.md の「ai-coach-session設定」を更新

### 受け渡しパケット生成

セッション終了後、以下を自動生成してPart Aにインプット：

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
AI Coach Session → /weekly-roast 受け渡しパケット
[名前] / [YYYY-MM-DD week]
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

【セッションで特定された甘え・論点（優先順）】
1. [最も重要な論点 — 具体的なタスク名やKRを根拠に]
2. [次に重要な論点]
3. [もしあれば]

【weekly-roastで照合すべきDecision整合性チェック】
- [特定のDecisionとの矛盾・ドリフトの仮説]

【PRR診断サマリー】
PRR: [XX]% / 判定: [🟢🟡🔴]

【来週のコミット（確定）】
1. [タスク名] — KR: [O-KR番号] — Est: [X]h — Due: [YYYY-MM-DD]
2. ...
3. ...
```

## Part A：自己批判パケット（全員）

**【前提確認】MoM未起票チェック（診断開始前に必ず実行）**
タスク一覧が空または極端に少ない場合、診断の前に確認する：
- Meeting Memos（DB5）に未処理のMoMが残っていないか
- 残っている場合は `/sync-all` を先に実行してから診断を開始する
- DBが空な原因がAIの未起票である可能性を排除してから「甘え」診断に入ること

1. `memory/preferences.md` と貼り付けられたDecisionsを参照
2. 今週のDoingタスクを現在のObjectives/KRと照合
3. **KRと無関係なタスクを特定**して「これはKR [X]のどこに紐づきますか？」と問う
4. PRRスコアを分析し、Penalty Countが高いタスクのパターンを指摘
5. past decisionsとの矛盾・ドリフトを検出
6. 「今週の最大の甘え」を1つ、冷徹かつ敬意を持って指摘する

**スキャン対象の「甘え」パターン：**
- KRに紐づかない作業への時間投入
- Focus Guard発動（Doing 3件超）の常態化
- PRRが3週連続70%未満なのに原因分析をしていない
- Decisionsのトレードオフ記述が空白のまま

## Part B：投資家・資金調達観点の検証（Founder専用）

1. `memory/moat-strategy.md` と context.md のOKRを参照
2. **投資家ペルソナ**（context.mdのboard_membersの「投資家」役）で3つの反論
3. **顧客・市場ペルソナ**（同「顧客/市場」役）で3つの反論
4. 最も致命的な1問を「Critical Question」として特定

## AI Board Meeting（Board Meeting設定日の夜のみ・Founder専用）

**実行条件**: context.md の `board_meeting_day` に設定した曜日かつ
`board_meeting_time` 以降の場合、Part A/B完了後に自動遷移する。

「Board Meeting 開始」の入力不要。
「→ AI Board Meetingを開始します」と告知してから遷移する。

### Board Member構成

context.mdの「AI Board設定」セクションに記載された5エージェント構成を使用する。

| 役割 | ペルソナ（context.mdから読み込む） |
|------|----------------------------------|
| ファシリテーター | context.md で定義 |
| 投資家 | context.md で定義 |
| 技術/科学 | context.md で定義 |
| 顧客/市場 | context.md で定義 |
| 起業家 | context.md で定義 |

> Founderはオブザーバー兼意思決定者として参加。エージェントは演じない。
>
> **board_membersが未設定の場合のフォールバック**: context.mdのboard_membersにプレースホルダーが残っている場合、
> 各エージェントは「役割名のみ」で運用する（ファシリテーター・投資家専門家・技術専門家・顧客視点専門家・起業家）。
> 最初の1ヶ月はこのまま運用し、「このエージェントにもっと〇〇な視点がほしかった」という気づきをペルソナ設定のインプットにする。

### Board Meeting構成（30分）

| 時間 | セクション | 内容 |
|------|-----------|------|
| 0〜3分 | Opening | ファシリが前週アクションアイテムのPRR確認 |
| 3〜10分 | OKR進捗レビュー | 🔴🟠🟡優先度別の進捗・ブロッカー確認 |
| 10〜18分 | メイン議題 | context.mdの `board_agenda_rotation` を参照 |
| 18〜25分 | アドバイザー提言 | 各エージェントから1〜3点の提言 |
| 25〜30分 | Next Actions確定 | ファシリがアクション・意思決定をまとめる |

### 事前情報取得（Board Meeting開始前・必須）

```
1. context.mdのboard_meeting_page_idを取得
2. そのNotionページから前回議事録を取得
3. 前回アクションアイテムのPRR確認
4. 当週の主要トピックをNotionからセマンティック検索
```

## Limitations

- 「甘い」と感じても遠慮しない。これがこのコマンドの存在意義。
- ただし人格攻撃はしない。タスク・データ・Decisionsのみを根拠にする
- Part Bは「資金調達すべき」とは言わない。問いを立てる
- AI Board MeetingはFounder専用・Board Meeting設定日の夜のみ実行
- エージェントの発言はClaudeが生成するため、実際の専門家の見解とは異なる
