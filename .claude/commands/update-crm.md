# /update-crm — 顧客開発・営業パイプライン管理

**発動コマンド**: `/update-crm` または `/sync-all` 実行時に自動判定
**Phase**: 2以降（Phase 1でも利用可）

## 設計思想

「創業者の作りたいもの」ではなく、「顧客が切実に痛がっている課題」がロードマップを決める。
顧客との対話から「信号」を抽出し、技術タスクへ物理的に配線する。

---

## Market Friction Score（市場フリクションスコア）

議事録テキストから顧客の「痛みの切実度」を1-10でAIが算出する：

```
スコアリング基準:

9-10: 「今すぐ解決しないと事業が止まる」レベル
      → キーワード: 「毎週X時間かかる」「コンプライアンス違反になる」「競合に負ける」

7-8:  「解決したいが今すぐではない」レベル
      → キーワード: 「いつか改善したい」「不便だが慣れている」「予算があれば」

5-6:  「あれば便利」レベル
      → キーワード: 「面白そう」「検討しても良い」

1-4:  「課題と認識していない」レベル
      → キーワード: 曖昧な賛同、具体的な痛みの欠如
```

**PMF Signal**：Pain Score ≥ 7 の顧客が全インタビューの30%を超えたらPMF方向性が見えてきた証拠。

---

## 実行プロトコル

### 議事録からの自動抽出

`/sync-all` で顧客MTGの議事録が入力された場合：

1. **顧客名・組織を特定** → Organizations DB に存在しない場合は新規作成を提案
2. **Pain Scoreを算出** → 発言内容からスコアリング
3. **次のアクションを抽出** → Tasks DB に登録を提案
4. **Stage を更新** → Lead/Qualified/Active/Closed のどれかを判定
5. **CRM更新のサマリーを報告**

### 手動実行時

```
「どの顧客の情報を更新しますか？
 または新しい顧客情報を入力してください」

入力形式:
- 会社名：
- 担当者名：
- 役職：
- 打ち合わせの内容（箇条書き可）：
- 次のアクション：
- この顧客のPain Score（1-10）：

→ Organizations DB + Contacts DB + Tasks DB を一括更新することを提案
```

---

## PMF Score の計算・報告

毎週の `/weekly-roast` 時に自動計算して報告する：

```
PMF Score = Pain Score ≥ 7 の顧客数 ÷ 全インタビュー顧客数

目安:
- 0-10%:  まだPMFの方向性が見えていない
- 10-30%: 初期シグナルあり。ペルソナを絞り込む時期
- 30%+:   PMF方向性が見えてきた
- 50%+:   PMFに到達しつつある
```

## Stage 別のアクション提案

| Stage | 定義 | AIが促すアクション |
|-------|------|-----------------|
| Lead | 接触済み、課題確認前 | インタビュー設定を提案 |
| Qualified | Pain Score ≥ 5 確認済み | PoC提案の準備を提案 |
| Active | PoC/パイロット進行中 | 週次確認タスクを設定 |
| Closed-Won | 契約締結 | decisions.mdへの記録を提案 |
| Closed-Lost | 失注 | 失注理由の記録を必須化 |
