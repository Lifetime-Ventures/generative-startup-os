# /narrative-check — ナラティブ整合性・Bus Factor チェック

**発動コマンド**: `/narrative-check [資料名または内容]`
**Phase**: 3（Phase 2後半でも利用可）

## Part 1: ナラティブ整合性チェック

ピッチ・採用メッセージ・顧客提案・投資家報告が
「一つの一貫したストーリー」として整合しているかを確認する。

### 5つのナラティブ軸チェック

```
1. 市場の課題（Problem）
   「この市場でなぜ今この問題が解けていないか」
   → decisions.mdの最新の市場認識と一致しているか

2. ソリューションのユニークネス（Solution）
   「なぜ我々の解決策がベストか」
   → moat-strategy.mdのActive Moatと整合しているか

3. 顧客の切実度（Customer Pain）
   「誰がどれほど困っているか」
   → Organizations DBのPain Score上位顧客と一致しているか

4. チームの強み（Team）
   「なぜ我々がこれを実現できるか」
   → preferences.mdの文化コードと一致しているか

5. 事業モデルの持続性（Business Model）
   「どうやって持続的に価値を届けるか」
   → OKRのKRと整合しているか
```

### チェック結果の報告形式

```
✅ 整合: [軸名] → [理由]
⚠️ 要確認: [軸名] → [ズレの内容と推奨修正]
❌ 不整合: [軸名] → [矛盾の内容と決定が必要な判断]
```

## Part 2: Bus Factor（属人化リスク）計算

「創業者が突然いなくなっても事業が継続できるか」を定量化する。

### Bus Factor スコアリング

```
以下の項目をチェックして Bus Factor スコアを算出:

高リスク（Bus Factor = 1）の兆候:
- decisions.mdの直近20件で特定の1人だけが判断者になっている
- コアとなる技術的知識が memory/ に文書化されていない
- 顧客関係が特定の1人に依存している（Contacts DBで確認）
- team/ フォルダに他のメンバーのcontext.mdが存在しない

スコア:
  0-2項目: Bus Factor = 3+（安全）✅
  3項目:   Bus Factor = 2（注意）⚠️
  4項目:   Bus Factor = 1（危険）🔴

Bus Factor 1 の場合:
  「以下の知識移転を今週中に実施することを推奨します：
   1. [文書化すべき暗黙知]
   2. [引き継ぐべき顧客関係]
   3. [/onboard-me で共有すべき意思決定の文脈]」
```

---

## Part 3: /narrative-check [資料] モード

ピッチデッキや提案書のテキストを入力すると：

1. 5つのナラティブ軸それぞれとの整合性をチェック
2. decisions.mdやmoat-strategy.mdと矛盾する記述を検出
3. 修正案を提示

使い方：
```
/narrative-check
[ピッチデッキや提案書のテキストをここに貼り付け]
```
